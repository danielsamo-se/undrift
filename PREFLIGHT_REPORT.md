## Key technical findings

1. **mcp 2.x breaking rename.** `from mcp.server.fastmcp import FastMCP` raises `ModuleNotFoundError` in 2.3.0, so tutorials written for 1.x do not run. The replacement is `MCPServer(...).streamable_http_app(streamable_http_path=..., transport_security=...)`.
2. **The tunnel would have been rejected by default.** With the default `host="127.0.0.1"`, the SDK auto-enables DNS-rebinding protection for localhost Host headers only. cloudflared forwards `Host: <x>.trycloudflare.com`, which gets 421. The fix adds the exact public host to `TransportSecuritySettings.allowed_hosts`; protection is not disabled. There is no wildcard-subdomain support (only `host:*` port wildcards), so the host must be updated on every Quick Tunnel restart.
3. **Lifespan.** The Starlette app returned by `streamable_http_app()` runs `session_manager.run()` in its own lifespan. We serve that app directly, wrapped only in a pass-through ASGI logger, so lifespan works without FastAPI. If FastAPI is added later, its lifespan must enter `mcp.session_manager.run()`.
4. **Stateless + JSON responses** (`stateless_http=True`, `json_response=True`). Each POST is self-contained, with no session affinity or SSE streams through the proxy. Both can be switched back with `MCP_STATELESS=0` / `MCP_JSON_RESPONSE=0` if Cominty's client needs sessions.
5. **Forwarded headers.** Uvicorn trusts `X-Forwarded-*` only from `127.0.0.1` (cloudflared runs locally). The server binds `127.0.0.1` only, so it is never directly reachable from the LAN.
6. **Leak vector in the Cominty SDK.** `client.mcp.list()` returns `mcp_url`, which includes the secret path. `spike.py` never prints it; it only reports whether host and path match.
7. **Model identity at runtime is a display string.** `LlmStep.data.model` is the only per-run model signal, and there is no model id or per-model cost. With a single-model chain no failover is possible, so the configured chain plus the model gate is the primary guarantee; the stream value corroborates it.
8. **Subagent delegation hides MCP calls.** The Sonnet 5.5 orchestrator handed retrieval to a built-in `subagent` tool. The SDK stream and persisted events show only that one call; the nested MCP calls and the subagent's model and steps are invisible. Our own server log is therefore the only authoritative record of MCP invocations. Recommended next step: have `server.py` append each tool call (name, args, timestamp, user agent) to a git-ignored JSONL file that `spike.py` reads and correlates by time window. This needs a server restart, so it is not done yet. Telling the agent "do not delegate to subagents" in the instructions is an alternative to evaluate.
9. **No hard budget control.** The Cominty SDK exposes `max_steps` (tool rounds per message, rough: up to `max_steps+1`) but no spending limit, and cost is known only after the run. Hence `spike.py` makes no paid call without `--run`, does one run per invocation, and uses `max_steps=6`.

## Security posture (preflight only)

- The secret URL path (256-bit `secrets.token_urlsafe(32)`) is a **temporary** bearer-in-URL. It can leak through anything that logs full URLs, such as proxies, the Cominty UI, or browser history. Acceptable only because the data is fictional and every tool is read-only.
- Before any write tool exists, move to OAuth (the Cominty form has OAuth Client ID/Secret fields).

## Not done (by design)

No write tools, policy engine, SQLite, frontend, GitHub, Vercel, Notion, or Memory integration. No second agent. No permanent tunnel or deployment.
